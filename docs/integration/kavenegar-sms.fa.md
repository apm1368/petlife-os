# اتصال پیامک کاوه‌نگار: وضعیت و راهنمای ادامه

- آخرین به‌روزرسانی: ۲۱ آبان ۱۴۰۵ (2026-11-12)
- شاخه‌ی کد: `claude/kavenegar-sms`
- مستندات رسمی: https://kavenegar.com/rest.html

> هیچ کلید، رمز یا شماره‌ی شخصی‌ای در این سند نیست. مخزن عمومی است. مقدارهای واقعی فقط روی سرور، در `apps/api/.env` نگه داشته می‌شوند.

## خلاصه‌ی وضعیت

| موضوع | وضعیت |
|---|---|
| تصمیم مالک | کاوه‌نگار جای فراز اس‌ام‌اس را می‌گیرد، هم برای کد ورود و هم برای پیامک‌های اطلاع‌رسانی |
| کد اتصال | نوشته شده و در این شاخه است؛ هنوز ادغام و منتشر **نشده** |
| روی opetlife.ir | هنوز `OTP_PROVIDER=dev` و `MESSAGING_PROVIDER=dev` است، یعنی **هیچ پیامکی واقعاً ارسال نمی‌شود** |
| کلید API کاوه‌نگار | معتبر است و روی سرور ذخیره شده |
| مانع فعلی | **خط ارسال معتبر.** خطی که داده شد، در ارسال واقعی رد شد (خطای ۴۱۲). مالک در حال خرید خط است |

## کارهایی که انجام شد و نتیجه‌ی هرکدام (۲۱ آبان ۱۴۰۵)

همه‌ی آزمایش‌ها از روی خود سرور سایت انجام شد.

| آزمایش | نتیجه | معنی |
|---|---|---|
| `utils/getdate` | ۲۰۰، در کمتر از ۰٫۱ ثانیه | سرور به `api.kavenegar.com` دسترسی دارد |
| `account/info` با کلید مالک | ۲۰۰ | کلید معتبر است. حساب از نوع Master است و شارژ دارد |
| `account/config` | `defaultsender` خالی است | حساب خط پیش‌فرض ندارد، پس در ارسال معمولی باید خط را صریحاً فرستاد |
| `verify/templatelist` | ۲۰۰ | این حساب با سرویس دیگری از مالک مشترک است و شارژش هم مشترک مصرف می‌شود. هنوز الگویی برای اپت لایف ساخته نشده |
| `verify/addtemplate` (ساخت الگوی `opetlifeotp`) | **۴۲۶** | «استفاده از این متد نیازمند سرویس پیشرفته می‌باشد» |
| `verify/lookup` | **۴۲۶** | ارسال کد با الگو در پلن **استاندارد** ممکن نیست. سرویس‌های دیگری هم که روی این حساب از Verify استفاده می‌کنند، فعلاً همین خطا را می‌گیرند |
| `sms/send` بدون خط | ۴۱۲ | ارسال معمولی در پلن استاندارد **مجاز است**؛ فقط خط لازم دارد |
| `sms/send` با خط ارائه‌شده (خط بین‌المللی با پیش‌شماره‌ی ‎+1)، در سه قالب `00…`، `+…` و بدون پیش‌شماره | **۴۱۲** در هر سه حالت | «ارسال کننده نامعتبر است». این خط به‌عنوان فرستنده‌ی این حساب پذیرفته نمی‌شود. هیچ پیامکی ارسال نشد و هزینه‌ای کم نشد |

نکته: درخواستی که گیرنده‌ی نامعتبر دارد (۴۱۱) قبل از بررسی فرستنده رد می‌شود. پس فقط ارسال به یک شماره‌ی واقعی نشان می‌دهد که خط درست است یا نه.

## آنچه کد این شاخه اضافه می‌کند

- **کلاینت کاوه‌نگار** (`apps/api/src/common/kavenegar/`)
  - درخواست‌ها با `POST` و `form-urlencoded` فرستاده می‌شوند و timeout دارند.
  - کلید API در مسیر URL است، پس URL هیچ‌وقت در لاگ یا پیام خطا نمی‌آید. فقط کد خطا برمی‌گردد (مثلاً `KAVENEGAR_412`).
  - طبقه‌بندی خطاها:
    - **گذرا** (ارسال دوباره ممکن است): ۴۰۲، ۴۰۸، ۴۰۹، ۴۵۱، خطاهای ۵xx سرور، timeout و قطعی شبکه
    - **دائمی:** بقیه‌ی کدهای جدول ۱ مستندات، مثل ۴۰۳ کلید نامعتبر، ۴۱۲ فرستنده‌ی نامعتبر، ۴۱۸ کمبود شارژ، ۴۲۴ الگوی پیدانشده، ۴۲۶ نیاز به سرویس پیشرفته و ۵۰۱ حساب آزمایشی
- **ارسال کد ورود** (`apps/api/src/modules/auth/otp/kavenegar-otp.provider.ts`) دو حالت دارد:
  1. اگر `KAVENEGAR_OTP_TEMPLATE` تنظیم شده باشد، کد با **Verify Lookup** فرستاده می‌شود. این حالت سرویس پیشرفته و الگوی تأییدشده لازم دارد.
  2. در غیر این صورت کد به‌صورت **پیامک معمولی** از `KAVENEGAR_SENDER` می‌رود، با این متن:
     «کد تأیید اپت لایف: ۱۲۳۴۵۶ / این کد را به کسی ندهید.»
     در این متن عمداً لینک یا دامنه نیست، چون بعضی خط‌ها لینک را محدود می‌کنند (خطای ۴۲۰).
  - خطای ۴۵۱ (درخواست بیش از حد) به‌صورت محدودیت ارسال دوباره‌ی کد به کاربر نشان داده می‌شود.
- **پیامک اطلاع‌رسانی** (`apps/api/src/modules/notifications/messaging/kavenegar-sms.adapter.ts`)
  - متن کامل پیام از `KAVENEGAR_SENDER` فرستاده می‌شود.
  - وضعیت «ارسال‌شده» یعنی کاوه‌نگار پیام را پذیرفته، نه این‌که به گیرنده رسیده.
- **محافظت از حریم خصوصی:** همه‌ی ارسال‌های معمولی با `hide=1` فرستاده می‌شوند، تا شماره‌ی گیرنده در فهرست ارسال‌ها و پنل کاوه‌نگار دیده نشود.
- **پایگاه داده:** مقدار `KAVENEGAR` به enum `MessagingProvider` اضافه شده، با migration `20261113150000_messaging_provider_kavenegar`.
- **پنل ادمین:** صفحه‌ی پیام‌رسانی و وضعیت سیستم کاوه‌نگار را نشان می‌دهند و می‌گویند کدام تنظیم کم است. متن‌ها به fa، en، de و es هستند.
- فراز اس‌ام‌اس حذف نشده و هنوز با `faraz` قابل انتخاب است.

## تنظیمات سرور (`apps/api/.env`)

| کلید | مقدار | وضعیت فعلی روی سرور |
|---|---|---|
| `KAVENEGAR_API_KEY` | کلید API از پنل | ✅ گذاشته شده |
| `KAVENEGAR_SENDER` | شماره‌ی خط (فقط رقم) | ⚠️ خط ردشده گذاشته شده؛ **بعد از خرید خط باید عوض شود** |
| `KAVENEGAR_ENABLED` | `true` | ⏳ بعد از انتشار کد |
| `KAVENEGAR_OTP_TEMPLATE` | `opetlifeotp` | ⏳ فقط اگر سرویس پیشرفته فعال شد و الگو تأیید شد |
| `OTP_PROVIDER` | `kavenegar` | ⏳ بعد از انتشار کد (الان `dev` است) |
| `MESSAGING_PROVIDER` | `kavenegar` | ⏳ بعد از انتشار کد (الان `dev` است) |
| `MESSAGING_SANDBOX_MODE` | `production` | ⏳ آخرین قدم، بعد از آزمایش موفق |

**ترتیب این کارها مهم است:**
- `OTP_PROVIDER` و `MESSAGING_PROVIDER` را **فقط بعد از** انتشار این کد روی opetlife.ir به `kavenegar` تغییر دهید. کد قبلی مقدار `kavenegar` را نمی‌شناسد و API بالا نمی‌آید. اسکریپت `deploy.sh` هم در rollback همان مقدارهای اول استقرار را برمی‌گرداند.
- PM2 متغیرها را داخل خود پروسه نگه می‌دارد. پس بعد از ویرایش `.env` باید API با `--update-env` دوباره راه‌اندازی شود.

## قدم‌های باقی‌مانده

**کار مالک (در پنل کاوه‌نگار):**
1. **یک خط اختصاصی بخرید و فعال کنید.** خط‌های ۱۰۰۰، ۲۰۰۰ یا ۳۰۰۰ برای پیامک خدماتی مناسب‌اند. شماره‌ی خط باید در «خطوط من» با وضعیت فعال دیده شود.
2. **آی‌پی سرور را در «تنظیمات ← تنظیمات امنیتی» ثبت کنید.** این کار برای خط‌های بین‌المللی لازم است و برای امنیت کلید هم توصیه می‌شود.
3. *(اختیاری، توصیه‌شده)* **سرویس پیشرفته را فعال کنید.** آن وقت کد ورود با الگو، با اولویت بالا و بدون فیلتر تبلیغاتی ارسال می‌شود. الگوی پیشنهادی:
   - نام: `opetlifeotp` (نام الگو فقط حروف و عدد انگلیسی است و فاصله یا `_` ندارد)
   - نوع: پیامک، استفاده در وب‌سایت
   - متن (۶۱ حرف، یک پیامک):
     ```
     کد تأیید اپت لایف: %token
     این کد را به کسی ندهید.
     opetlife.ir
     ```
   - با کلید API می‌شود این الگو را با `verify/addtemplate` از سرور هم ساخت. بعد باید منتظر وضعیت `Approved` ماند.
4. موجودی حساب را برای راه‌اندازی واقعی شارژ کنید.

**کار فنی (بعد از آماده شدن خط):**
1. شماره‌ی خط جدید را در `KAVENEGAR_SENDER` بگذارید. با یک `sms/send` به شماره‌ی مالک آزمایش کنید و جواب ۲۰۰ بگیرید.
2. این PR را ادغام کنید. با push به `main` استقرار خودکار انجام می‌شود و migration اجرا می‌شود.
3. بعد از سالم بودن استقرار، این مقدارها را بگذارید و API را با `--update-env` دوباره راه‌اندازی کنید:
   - `KAVENEGAR_ENABLED=true`
   - `OTP_PROVIDER=kavenegar`
   - `MESSAGING_PROVIDER=kavenegar`
4. ورود با شماره‌ی موبایل را روی opetlife.ir آزمایش کنید. کد باید برسد.
5. بعد از آن `MESSAGING_SANDBOX_MODE=production` را بگذارید تا پیامک‌های اطلاع‌رسانی (مثل یادآوری نوبت) هم واقعاً ارسال شوند. وضعیت را در پنل ادمین ← پیام‌رسانی بررسی کنید.
6. وقتی پیامک و ایمیل هر دو فعال شدند، بازگرداندن ورود دومرحله‌ای ادمین (PR #295) دوباره قابل بررسی است، چون مالک آن را تا آن زمان متوقف کرده است.
