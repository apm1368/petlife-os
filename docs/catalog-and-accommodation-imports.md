# Catalog and accommodation imports

## Product catalog import

`/admin/commerce/catalog-imports` queues bounded Digikala imports. The admin supplies a source product/category URL and maps the destination to an existing PET LIFE category; optional brand mapping is an explicit admin choice. Requests are idempotent and persisted as jobs with progress, cancellation, retry/backoff, per-item results and restart recovery. A job is limited to 20 URLs, 10 pages and 100 products (the admin screen currently uses 5 pages/50 products).

The parser consumes only public Schema.org `Product` JSON-LD from HTML. It does not call Digikala's unofficial seller or internal APIs. It records product name, any explicitly supplied alternate name, brand/category text, description, structured specifications, canonical URL and gallery candidates. No machine translation is fabricated. Since the catalog decision C-03 requires exactly three images, import requires three validated images; insufficient media remains in `NEEDS_REVIEW` and does not create a catalog product.

Imported items create a `Product` with `DRAFT` status, exactly three repository-owned `ProductMedia` rows and no `ProductVariant`, seller offer, price, inventory, order, or transaction. Source image bytes are type/signature/size checked, fetched only from allow-listed Digikala hosts over the existing SSRF-safe fetcher, and copied to the existing storage driver. The source media URLs remain on the media/source observation for attribution; the image is not transformed, so any source watermark is preserved. Repeated source observations do not mutate the product. A changed source snapshot stays pending until an admin explicitly applies or rejects it with a reason and an audit record.

The source's live terms and detailed product-page layout were not established by this implementation pass. A small read-only pilot on 2026-11-06 fetched `robots.txt` (HTTP 200) and a product-category URL present in Digikala's published sitemap (HTTP 200, 13,628 bytes). That page returned a Next.js `/routing` shell rather than category results or Product JSON-LD. Pilot: 1 category URL tested, 0 products discovered, 0 imported, 0 skipped, 1 failed schema/content check. No source price or stock was read or imported. Thus, the importer code remains tested only with synthetic parser fixtures; do not claim live product import compatibility. The public page access alone does not establish content or image reuse permission. The importer fails closed for query URLs, honors robots rules, and does not retry access denials, 429s, disallowed paths, or private/unsafe URLs.

## Accommodation connector — Jajiga (PL-10 in open PR #112)

The owner selected Jajiga in PL-10 (open PR #112); this is the active source decision and we are not reopening the Jajiga/Jabama comparison. PL-03 remains historically recorded in the decision log, with PL-10 selecting its source. C-12 continues to govern catalog imports only: central product identity is separate from seller price/inventory. PL-09 in #112 adds the seller request/review flow and does not replace C-12.

On 2026-11-06, read-only probes to `https://www.jajiga.com` found `robots.txt` HTTP 200 (`User-agent: *`, `Allow: /`, with listed exclusions) and a public pet-filter search at `/s?rule[0]=pet` returning HTTP 200. The server-rendered response reported 3,323 matching stays and six cards on the observed first page; these are source-reported counts, not a verified nationwide census. The six cards exposed numeric source IDs, canonical `/room/{id}` URLs, title, city/province, max guest capacity, and an `is_pet_friendly` marker. One listing page was fetched read-only and returned title/description/pictures fields, but its generic pet-rule localization was not listing-specific. No date-bound price/availability, guest/date quote, specific animal rules, or complete pagination was observed.

Pilot totals: 6 discovered on the first observed page; 0 imported to production; 6 skipped from persistent import pending content-use terms review; 0 request/schema failures. There was no production write. The adapter now parses the public search response and can sync factual listing metadata daily with incomplete-scope safety; it intentionally copies no long descriptions or images, records no date-less base price, does not claim live availability, and holds results in draft/admin review. A missing item on the single observed page cannot mark a listing as removed. Outbound reservation links point to the exact canonical Jajiga detail page.

Access conditions verified: public unauthenticated GETs succeeded; the observed robots file permits general public paths except its stated exclusions; the sitemap is publicly exposed. This is not a partner API or content license. The `/rules` response was an app shell with no readable reuse terms, and the listing footer states site content rights belong to Jajiga's operator. Image/description reuse permission was not verified; source images and long descriptions therefore remain unused. These evidence boundaries are persisted with the source configuration. Daily sync is configured at 1,440 minutes, with images disabled and automatic publishing off; it becomes active only when its migration is deployed. Until then it is NOT LIVE.

## Operational boundary

- The importer is admin-only (`commerce.view` to read, `commerce.manage` to queue/cancel/review).
- Rejected or blocked source access is surfaced as job/item error or an operator task after terminal job failure; no proxy, identity rotation, undocumented endpoint, or synthetic source result is used.
- Empty product categories and import queues remain genuinely empty. A no-result job is a failure/partial result, not a simulated success.
- Accommodation links remain original-source outbound links. No booking, payment, live availability or guaranteed pet acceptance is represented by these imports.
