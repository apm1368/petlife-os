# Localization rollout status

The public landing route is available in Persian, English, German and Spanish. Persian uses RTL; the other three use LTR. The German and Spanish landing copy includes the public navigation, service descriptions, partner entry, trust/privacy copy, footer and image-credit disclosures. The existing approved landing composition and source images are unchanged; the German and Spanish hero use the existing English-labelled artwork because the pavilion labels are baked into the image.

This is not full application localization. The account preference API and database support saving all four locales (fa/en/de/es). The shared member navigation (desktop, mobile and Explore sheet), Explore index and Account navigation now have explicit copy in all four locales; links retain the active locale. Registration, password login, phone/OTP login, forgot/reset password, auth-shell copy and household collaboration copy also have German/Spanish translations. Household copy covers members, invitations, pet permissions, access presets, confirmation actions and access history. Account dates use the selected locale (fa retains Jalali) and account counts use locale-specific number formatting. The DE/ES auth catalogs overlay the English catalog so unfinished message keys remain readable instead of raising missing-key errors. These page families have focused component tests. The landing and personal-settings locale selector/calendar explanation were already localized in all four languages.

Account settings page bodies (outside the language/calendar copy), pet/health, booking, provider, seller, shop, admin, support and legal copy remain partially or mostly Persian/English only. German and Spanish message catalogs currently translate auth-specific branches; other keys fall back to English to avoid missing-key errors. Notification and trip-checklist copy also falls back to English for German and Spanish; German/Spanish SMS templates are not implemented and must not be simulated. Outside the components named above, do not present fallback text as a completed translation.

Next slices: remaining account settings; customer pet/health/care calendar; commerce and provider/seller workflows; support/legal; travel/community/partner; backoffice and notifications. Each slice must include locale-aware date/number formats where relevant, route-preserving language switching, accessibility, tests and a missing-key check before it is reported complete. Account language persistence remains covered by the existing #118 API/database implementation; this batch does not alter that contract.

### Public service-provider discovery and profiles (PR #128 slice based on #118)

The service/vet discovery page and public provider profile are being localized in fa/en/de/es. The discovery surface includes search, categories, filter controls and chips, sorting, verification labels, counts, prices, availability, empty/error states, favorites' accessible labels and the map-provider-unavailable notice. The profile includes section anchors, verification, services, booking mode, duration and price labels, provider availability headings, team roles, about/location/review/policy/FAQ chrome, loading/error/empty labels, cancellation and booking-panel copy. Week availability dates use the selected Gregorian locale for en/de/es and retain Persian Jalali behavior. Counts, prices and digits use locale-aware formatting, and internal booking links preserve the route locale. Search, availability, favorites, booking links and ranking behavior are unchanged; no API/data contract or booking behavior was changed.

The map remains clearly unavailable until a real map provider is connected. Provider-authored descriptions, FAQs, policy text, review content, service names, staff names, city/address and other source content intentionally remain as supplied and are not automatically translated. Provider console, booking creation/rescheduling forms, and API-generated error detail remain incomplete for German/Spanish. No fake providers, results, ratings, availability, prices or map results are added. German/Spanish SMS templates and delivery are not implemented.
