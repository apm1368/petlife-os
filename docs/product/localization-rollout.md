# Localization rollout status

The public landing route is available in Persian, English, German and Spanish. Persian uses RTL; the other three use LTR. The German and Spanish landing copy includes the public navigation, service descriptions, partner entry, trust/privacy copy, footer and image-credit disclosures. The existing approved landing composition and source images are unchanged; the German and Spanish hero use the existing English-labelled artwork because the pavilion labels are baked into the image.

This is not full application localization. The account preference API and database support saving all four locales (fa/en/de/es). The shared member navigation (desktop, mobile and Explore sheet), Explore index and Account navigation now have explicit copy in all four locales; links retain the active locale. Registration, password login, phone/OTP login, forgot/reset password, auth-shell copy and household collaboration copy also have German/Spanish translations. Household copy covers members, invitations, pet permissions, access presets, confirmation actions and access history. Account dates use the selected locale (fa retains Jalali) and account counts use locale-specific number formatting. The DE/ES auth catalogs overlay the English catalog so unfinished message keys remain readable instead of raising missing-key errors. These page families have focused component tests. The landing and personal-settings locale selector/calendar explanation were already localized in all four languages.

Account settings page bodies (outside the language/calendar copy), pet/health, booking, provider, seller, shop checkout/orders/repeat delivery/favorites, admin, support and legal copy remain partially or mostly Persian/English only. German and Spanish message catalogs translate auth, household, landing, personal settings, pet profile/care, and the shop discovery/cart branches documented below; other keys fall back to English to avoid missing-key errors. Notification and trip-checklist copy also falls back to English for German and Spanish; German/Spanish SMS templates are not implemented and must not be simulated. Outside the components named above, do not present fallback text as a completed translation.

### Shop discovery and cart (PR slice based on #118)

German and Spanish now have explicit copy for customer shop home, catalog search/results and filters, product details, compatibility guidance, cart, stock/rating labels, and shared commerce navigation/feedback. Shop-facing prices retain the same Rial-to-Toman display conversion; only digit grouping follows fa/en/de/es locale. Persian stays RTL with Jalali behavior unchanged; English remains the fallback source. Product titles, seller names, brands, catalog data and offer values remain server-provided data, not translated or fabricated.

Not included: checkout-specific copy and flows, order history/details, repeat-delivery management, favorites, seller onboarding/catalog/offer management, and commerce backoffice. These remain English fallback in German/Spanish. German/Spanish SMS templates and delivery are still absent. CI is the production-build gate for this slice; the local disk is constrained and a full local build is deferred.

Next slices: pet/health depth and medical records; seller catalog; checkout/order/repeat-delivery; provider/booking; support/legal; travel/community/partner; backoffice and notifications. Each slice must include locale-aware date/number formats where relevant, route-preserving language switching, accessibility, tests and a missing-key check before it is reported complete. Account language persistence remains covered by the existing #118 API/database implementation; this batch does not alter that contract.

### Health basics, care profile and care calendar (branch `feat/i18n-health-de-es`, based on #122)

German and Spanish now have explicit translations for the core health namespace (overview, allergies, conditions, medications, vaccination summary and nutrition basics), care profile, common actions and care calendar. Calendar controls, loading/empty messages and booking titles are localized; dates use the selected locale and Tehran timezone, with Persian Jalali behavior retained. German and Spanish month grids start on Monday. Medical-record-derived care reminder kinds now have fa/en/de/es labels in the calendar, pet overview, care sheet and year-review breakdown. Relevant decisions: GC-09 (reviewed repo translations), GC-10 (RTL/LTR), GC-12 (locale calendar and timezone), GC-15 (localized reference labels).

This is a partial localization slice, not full health/care coverage. The health-depth and advanced health namespaces, document/lab/imaging/referral and clinical pages, share/access pages, `rollout.records`, Care Center and care-suggestion/provider workflows still use English fallback or are otherwise untranslated in German/Spanish. SMS templates/delivery are not implemented. The full web tests/build on the eventual PR head remain required before merge.
