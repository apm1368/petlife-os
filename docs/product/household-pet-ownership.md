# ماژول خانواده و انتقال مالکیت پت

> کدهای تصمیم: **ID-01، ID-02، ID-03، ID-05، ID-06، ID-07**
> مرجع الزام‌آور: [سند تصمیم‌ها](../decisions.md)
> وضعیت: پیاده‌سازی‌شده در `main` — API + UI + تست

---

## ۱. چرا این ماژول وجود داشت

پیش از این کار، مالکیت پت **صریح نبود**. `Pet` فقط `householdId` داشت و نقش
«مالک» از نقش عضوی در خانواده استنباط می‌شد. این سه چیز را ناممکن می‌کرد:

| خواستهٔ سند تصمیم | چرا پیش از این ممکن نبود |
| --- | --- |
| ID-01: هر پت **دقیقاً یک** مالک اصلی دارد | یک خانواده می‌توانست چند عضو `OWNER` داشته باشد؛ رکورد پت هیچ‌جا اسم مالک را نداشت |
| ID-01: انتقال مالکیت با **تأیید دو طرف** | هیچ مسیری برای «پیشنهاد → تأیید» وجود نداشت |
| ID-05: خاطرات با انتخاب مالک قبلی، هزینه‌ها **نمی‌رود** | جابه‌جایی پروندهٔ پت یک عملیات بیرونی بود که هیچ‌جا مدل نداشت |

این ماژول هر سه را به یک منبع حقیقت صریح تبدیل می‌کند: `pet_ownerships`.

---

## ۲. مدل داده

### ۲.۱ `pet_ownerships` — مالک اصلی

هر پت **حداکثر یک** ردیف دارد (`@@unique([petId])`). این یکتایی، خودش
اجرای «دقیقاً یک» است — نه یک قرارداد شفاهی، بلکه یک محدودیت دیتابیس.

| ستون | نقش |
| --- | --- |
| `petId` | یکتا — یک پت، یک مالک |
| `ownerUserId` | مالک اصلی؛ همیشه عضوی از `Pet.householdId` |
| `householdId` | خانوادهٔ پت در لحظهٔ ثبت (برای audit) |
| `transferredAt` / `transferReason` | آخرین انتقال و دلیلش |

### ۲.۲ `pet_ownership_transfers` — درخواست انتقال

رکورد **توافق دوطرفه**. تا وقتی طرفین تأیید نکنند، هیچ چیزی جابه‌جا نمی‌شود.

وضعیت‌ها: `PENDING_REVIEW` → `ACCEPTED` | `DECLINED` | `CANCELLED` | `EXPIRED`
و `DISPUTED` (اختلاف — ثبت می‌شود ولی پت را جابه‌جا نمی‌کند).

### ۲.۳ `pet_memory_copies` — کپی فقط‌خواندنی (ID-02)

وقتی عضوی از خانواده جدا می‌شود، خاطراتی که **خودش** ثبت کرده به‌صورت
فقط‌خواندنی نگه داشته می‌شود. اصلِ خاطره حذف یا fork نمی‌شود — این رکورد یک
**اجازهٔ خواندن** روی خاطرهٔ اصلی است، با ایندکس یکتای `(memoryId, userId)`.

### ۲.۴ `subscriptions.payerUserId` — پرداخت‌کننده (ID-07)

پرداخت‌کنندهٔ ثبت‌شدهٔ اشتراک. تا وقتی انتقالی در انتظار تأیید اوست، تمدید
اشتراک **معلق** می‌ماند.

## ۳. قواعد کسب‌شده

### ۳.۱ تأیید دوطرفه، نه یک‌طرفه (ID-01)

```
مالک فعلی  →  POST /pet-ownership/pets/:petId/transfers   (پیشنهاد)
گیرنده      →  POST /pet-ownership/transfers/:id/accept   (تأیید)
                    ↓ فقط اینجا پت جابه‌جا می‌شود
```

- پیشنهاددهنده حتماً باید **مالک ثبت‌شده** باشد. هیچ‌کس به‌جای کس دیگر
  نمی‌تواند پیشنهاد بدهد.
- درخواست با `updateMany` روی وضعیت `PENDING_REVIEW` **claim** می‌شود، پس دو
  درخواست هم‌زمان هرگز انتقال را دوبار اعمال نمی‌کنند.
- فقط **یک** درخواست در انتظار برای هر پت مجاز است.

### ۳.۲ پلتفرم داوری نمی‌کند (ID-03)

> «اختلاف مالکیت: اپت‌لایف قضاوت نمی‌کند؛ مالک ثبت‌شده می‌ماند تا حکم مرجع
> رسمی یا توافق کتبی.»

هر یک از دو طرف می‌تواند اختلاف ثبت کند. نتیجه:

- پت **جابه‌جا نمی‌شود**؛
- مالک ثبت‌شده **تغییر نمی‌کند**؛
- اختلاف **ثبت** می‌شود تا وقتی حکم یا توافق کتبی برسد، سابقه داشته باشد.

### ۳.۳ چه چیزی با پت می‌رود و چه چیزی نمی‌رود

| داده | نتیجه | مبنا |
| --- | --- | --- |
| پروندهٔ سلامت | **می‌رود** (به پت چسبیده است) | ID-05 |
| رزروها | **می‌رود** — به خانوادهٔ جدید منتقل می‌شوند | ID-06 |
| یادآورها | **می‌رود** (به پت چسبیده‌اند) | ID-06 |
| اشتراک | پرداخت‌کننده به مالک جدید منتقل می‌شود | ID-07 |
| خاطرات | **به انتخاب مالک قبلی** | ID-05 |
| هزینه‌ها | **نمی‌رود** — نزد خانوادهٔ قبلی می‌ماند | ID-05 |

انتخاب مالک قبلی برای خاطرات هنگام پیشنهاد ثبت می‌شود:

| `memoryDisposition` | معنی |
| --- | --- |
| `TRANSFER` | خاطرات همراه پت منتقل می‌شوند |
| `RETAIN` (پیش‌فرض) | خاطرات نزد خانوادهٔ قبلی می‌مانند |
| `COPY_READ_ONLY` | اصل خاطرات می‌ماند، مالک جدید یک نسخهٔ فقط‌خواندنی می‌گیرد |

### ۳.۴ مالکیت ≠ دسترسی

هنگام اعمال انتقال، دو grant دسترسی هم جابه‌جا می‌شود:

- **مالک جدید** `OWNER_PRESET` را می‌گیرد — بدون آن، مالک پتی را می‌داشت که
  نمی‌توانست بازش کند. preset از `PetAccessService` import می‌شود، نه کپی
  می‌شود، تا هرگز drift نکند.
- **مالک قبلی** grant در سطح `owner` خود را از دست می‌دهد، ولی grant رزروِ
  ارائه‌دهنده یا اشتراک صریح دامپزشک دست‌نخورده می‌ماند (آن‌ها متعلق به
  خانواده نیستند).

### ۳.۵ توقف تمدید تا تأیید (ID-07)

> «پرداخت‌کنندهٔ موارد تکراری به مالک جدید منتقل می‌شود؛ تا تأیید او متوقف.»

در `SubscriptionBillingService.attemptRenewal`، اگر پرداخت‌کنندهٔ ثبت‌شده
طرف یک انتقالِ بی‌پاسخ باشد، تمدید **معلق** می‌ماند و لاگ می‌شود. شارژ کردن
مالک قبلی برای خانواده‌ای که دیگر اداره نمی‌کند دقیقاً همان چیزی است که این
تصمیم ممنوع می‌کند.

## ۴. API

| متد | مسیر | توضیح |
| --- | --- | --- |
| `GET` | `/pet-ownership/pets` | پت‌هایی که مالک اصلی‌شان هستید |
| `GET` | `/pet-ownership/pets/:petId` | مالک اصلی یک پت |
| `POST` | `/pet-ownership/pets/:petId/transfers` | پیشنهاد انتقال |
| `GET` | `/pet-ownership/transfers/incoming` | در انتظار پاسخ شما |
| `GET` | `/pet-ownership/transfers/outgoing` | پیشنهادهای شما |
| `GET` | `/pet-ownership/transfers` | همهٔ موارد مرتبط با شما |
| `GET` | `/pet-ownership/transfers/:id` | یک انتقال |
| `POST` | `/pet-ownership/transfers/:id/accept` | تأیید — پت جابه‌جا می‌شود |
| `POST` | `/pet-ownership/transfers/:id/decline` | رد کردن |
| `POST` | `/pet-ownership/transfers/:id/cancel` | لغو توسط مالک |
| `POST` | `/pet-ownership/transfers/:id/dispute` | ثبت اختلاف (پت جابه‌جا نمی‌شود) |
| `GET` | `/pet-ownership/memory-copies` | کپی‌های فقط‌خواندنی شما (ID-02) |

پاسخ `accept` فقط `ok` نیست؛ گزارش کاملی از آنچه جابه‌جا شد می‌دهد
(`movedBookings`، `movedMemories`، `retainedExpenses`، `subscriptionSuspended`)
تا هر دو طرف دقیقاً بدانند چه اتفاقی افتاده.

## ۵. UI

`/profile/household/ownership` با سه تب: **دریافتی** · **ارسالی** · **خاطرات من**.

- پنج حالت UI: بارگذاری، خالی، خطا (با بازیابی)، مجوز (پیام روشن)، پرشده.
- فارسی و انگلیسی.
- قبل از هر اقدام، یک dialog صریح می‌گوید چه اتفاقی می‌افتد: پروندهٔ سلامت
  می‌آید، خاطرات چه می‌شوند، هزینه‌ها کجا می‌مانند.

## ۷. آنچه این کار **نکرد**

- **ID-04** (فوت مالک → وارث پت / حالت یادبود) و **ID-08** (ادغام دو حساب با
  OTP) پیاده نشده‌اند — جریان‌های چندمرحله‌ای جدا با تأیید انسانی هستند.
- **ID-10** (انتقال مالکیت فروشگاه) متعلق به دامنهٔ سازمانی است، نه خانواده.
- **ID-12** (سوییچ بین چند خانواده با آواتار پت) در رابط موجود تا حدی هست؛
  این ماژول آن را گسترش نداده.
- مسیر «انتقال» از صفحهٔ پت هنوز UI ندارد؛ فقط صفحهٔ مالکیت و API کامل شده.
