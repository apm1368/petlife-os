# تنظیمات واقعی سامانه و اعلان عمومی

مبنا هنگام ایجاد شاخه: `9f2048d8afa4da4b66e1a291b31d0998ac1cc8df` از origin/stabilization/wave-1. این تغییر از پنج قرارداد موجود ادمین و GET /settings/public استفاده می‌کند؛ endpoint یا migration جدید ندارد.

- صفحه /[locale]/admin/settings هشت کلید واقعی registry، مقدار جاری، منشأ و درخواست‌های معلق را نشان می‌دهد. view/manage/approve جدا هستند؛ منو نیز settings.view می‌خواهد.
- تغییرات حساس فقط درخواست تأیید دوم ایجاد می‌کنند. وضعیت PENDING موفقیتِ اعمال تنظیم نیست. تأیید خود و لغو درخواست دیگران در رابط عرضه نمی‌شود؛ کنترل نهایی با سرور است.
- مقدار تومان با یک رقم اعشار بدون گردکردن به IRR صحیح تبدیل می‌شود. صفر مجاز است و حدود واقعی registry اعمال می‌شوند. رقم فارسی/عربی پشتیبانی می‌شود.
- شکست ذخیره پیش‌نویس و دلیل را نگه می‌دارد. تعارض نسخه نیازمند بازخوانی، بررسی مقدار تازه و تأیید مجدد است. تاریخچه فیلتر و صفحه‌بندی واقعی دارد.
- اعلان در قاب اعضا از API عمومی خوانده می‌شود؛ متن به‌صورت plain text با زبان و جهت درست نمایش می‌یابد. loading، خطا/تلاش مجدد و اعلان خالی جدا هستند. هیچ تنظیم داخلی از API ادمین به این قاب ارسال نمی‌شود.

## بررسی

- نصب frozen با pnpm 10.33.0 و Prisma واقعی در محیط مشترک این ادامه انجام شده؛ lockfile تغییر نکرده است. CI همین PR باید نصب تازه، تمام بررسی‌ها و build را تأیید کند.
- lint وب پاس شد (سه warning قبلی)؛ typecheck وب پاس شد.
- ۱۶ تست تنظیمات، منوی ادمین و اعلان پاس شد؛ شامل مجوز فقط‌خواندن، جلوگیری از تأیید خود، دقت IRR، null صریح، تعارض نسخه، حفظ پیش‌نویس و نمایش امن متن است. خطای اولیه نام مورد انتظار لینک در تست تازه به نام واقعی «Platform settings» اصلاح شد.
- هر ۲۲ تست موجود پوشه app-shell همراه اعلان پاس شد. تستی skip یا ضعیف نشده است.
- GET سایت زنده در این نشست فقط کلید platform.announcement را برگرداند و مقدار آن خالی بود. هیچ تنظیم زنده‌ای نوشته نشد.
