# موارد طرح فروشگاه که قرارداد بک‌اند ندارند

مبنای بررسی: `stabilization/wave-1` در commit `a5a672d`. این گزارش به معنی نبودن قابلیت در نسخه‌های بعدی نیست. فایل‌های بک‌اند فقط خوانده شده‌اند.

| مورد تصویری | وضعیت واقعی کد | تصمیم فرانت این مرحله |
| --- | --- | --- |
| عکس برای هر دسته‌بندی | `ProductCategoryDto` در `packages/types/src/index.ts` فقط id، parentId، name، slug و status دارد. `CatalogService.listCategories` همان قرارداد را برمی‌گرداند. | آیکون کتابخانه‌ای متناسب با slug؛ عکس محصولی به‌عنوان عکس دسته جعل نمی‌شود. |
| تصویر هر ردیف سبد خرید | `CartLineDto` تصویر ندارد. `ProductSummaryDto` و جزئیات کالا رسانه دارند، اما قرارداد سبد تصویر برنمی‌گرداند. | ردیف متنی کامل با عنوان، گونه کالا، فروشنده، تعداد، قیمت و هشدارها؛ بارگذاری جداگانه جزئیات تمام کالاها برای پرکردن عکس تحمیل نشده است. |
| کد تخفیف قابل ورود در خلاصه سفارش | سرویس‌ها و controllerهای commerce قرارداد ورود/اعتبارسنجی coupon ندارند؛ promotionهای واقعی با قیمت مؤثر سرور اعمال می‌شوند. | کادر بی‌عملیات کد تخفیف ساخته نشده؛ تخفیف واقعی سرور و انقضای آن نمایش داده می‌شود. |
| نشان Trending و فروش تضمینی | API امتیازهای واقعی و موجودی را دارد؛ trending یا آمار فروش تضمین‌شده ندارد. | نشان ساختگی نمایش داده نمی‌شود. |
| افزودن مستقیم هر کارت به سبد | افزودن نیازمند offerId، گونه کالا، موجودی و زمینه پت است. | کارت، جزئیات محصول را باز می‌کند؛ انتخاب فروشنده/گونه و هشدار سازگاری قبل از افزودن حفظ شده است. |
| عکس واقعی محصول و برند | URL رسانه از catalog می‌آید. همه محصولات الزاماً عکس ندارند؛ در مخزن seedهای قدیمی SVG هم وجود دارد. | تصویر واقعی کاتالوگ بدون جایگزینی با عکس محصول دیگری نمایش داده می‌شود. حالت بدون عکس آیکون خنثی دارد. تصاویر نمونه پوشه fixtures فقط برای بررسی کنترل‌شده‌اند و در برنامه وارد نشده‌اند. |

## پرامپت قابل تحویل به مسئول بک‌اند

```text
[codex→claude] تکمیل قرارداد رسانه فروشگاه مطابق طراحی تأییدشده
از آخرین stabilization/wave-1 شاخه جدا بساز. بدون تغییر رفتار قیمت‌گذاری یا موجودی:
۱. برای دسته‌های محصول، قرارداد optional imageUrl و alt محلی‌سازی‌شده را با مسیر مدیریت مجاز رسانه طراحی و پیاده کن؛ URL، MIME، دسترسی و مالکیت فایل را اعتبارسنجی کن.
۲. برای CartLineDto یک imageUrl nullable از رسانه همان product/variant با ترتیب انتخاب مشخص برگردان. در صورت حذف فایل یا نبود تصویر null بده. N+1 query ایجاد نکن. عکس کالاهای دیگر را جایگزین نکن.
۳. types و mapper و تست قرارداد را به‌روز کن. رفتار سبد چندفروشنده، کالای ناموجود و هشدارهای قیمت/سازگاری تغییر نکند.
۴. محصول‌های seed دارای تصویر برداری را جدا گزارش کن؛ بدون منبع و مجوز معتبر آن‌ها را با عکس برند یا محصول دیگری جایگزین نکن.
در PR قرارداد دقیق و نمونه پاسخ را به مسئول فرانت تحویل بده.
```

کد تخفیف، trending و افزودن مستقیم کارت به سبد برای اجرای طرح الزامی نیستند؛ توسعه بک‌اند آن‌ها نیاز به تصمیم محصول مستقل دارد. این مرحله آن‌ها را به‌عنوان قابلیت آماده معرفی نمی‌کند.
